# Fee Costs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Answer who pays CCIP the most and what a message costs: fee rankings on the Top pages (with a new Chains tab), a "What does a message cost?" picker on Flow with a typical-fee column on Top lanes, and on day pages and History the fee per message, the share paid in LINK, the fee mix and the take rate.

**Architecture:** The Worker's history publish gains two outputs. Each `top/{dim}.json` adds a `by_fees` ranking from the same `daily_breakdown` query, ordered by fees. A new `cost.json` comes from one D1 query with window functions: it ranks each route's priced fees over the last 30 complete days and returns one row per route, holding the nearest-rank 10th, 50th and 90th percentiles and the LINK and non-LINK medians. Both new fields are optional in the core schema. The site reads `by_fees` and `cost.json` at build time for the Top pages, and fetches `cost.json` in the browser for the Flow picker. Day pages and History compute the take rate, the fee per message and the fee mix from `history.json` fields that already exist.

**Tech Stack:** TypeScript (ESM), Vitest 4, Cloudflare Workers with D1 and R2 (`@cloudflare/vitest-plugin`), zod 4 (core), Astro 7, React 19, `d3-shape` (already a site dependency). No new data sources and no new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-09-fee-costs-design.md`.

## Global Constraints

- **No new data sources and no migration.** "The fee backfill is unchanged." Out of scope: "report cards, Telegram posts and the replay fee counter (sub-project 3); per-sender cost; any change to how fees are priced or stored."
- **Fee basis:** "always the overall typical fee. Show LINK against gas tokens only when a route had at least 20 LINK-paid messages in the window."
- **`cost.json`:**
  - Window: "the last 30 complete days (`today − 30 … yesterday`), over messages with `fee_usd IS NOT NULL`."
  - Constants: `COST_WINDOW_DAYS = 30`, `COST_MIN_MESSAGES = 5`, `COST_LINK_MIN_MESSAGES = 20`.
  - Shape: `{ from: day, to: day, lanes: [{ src, dst, messages, median_usd, p10_usd, p90_usd, link?: { messages, median_usd }, gas?: { messages, median_usd } }] }`. `src` and `dst` are chain selectors. "`gas` is every non-LINK fee."
  - Published in `publishHistoryFiles`, next to `history.json`. A failure alerts as `cost-publish` and doesn't stop the other history files.
- **Fee rankings:** `store.topBetween` gains `order: 'value' | 'fees'`.
  - value: `ORDER BY usd_value DESC, messages DESC`.
  - fees: `ORDER BY fee_usd DESC, usd_value DESC`, skipping keys whose `fee_usd` is null.
  - `TopFileSchema` gains `by_fees` as optional.
- **Addresses:**
  - Value pages stay at `/top/{dim}/{window}/`, and fees pages are at `/top/{dim}/{window}/fees/`.
  - Fees cards are at `/og/top/{dim}/{window}/fees.png`.
  - Picker links are `/flow/<window>/?from=<chain>&to=<chain>`.
- **Browser maths:**
  - Take rate: `fee_usd / usd_value × 10,000` basis points, "null when either value is null or zero".
  - Fee per message: `fee_usd / messages`.
  - Day LINK share: `fee_link_usd / fee_usd`.
  - Day fee mix: from the group columns in `history.json`, with Other "clamped at 0, as on Reserve".
- **Copy, verbatim from the spec:**
  - Picker: the title "What does a message cost?"; "most between $p10 and $p90"; "based on N messages, <from>–<to>"; "Paid in LINK: $X · in gas tokens: $Y"; "Not enough messages in the last 30 days to say."
  - Top: the "Value | Fees" tab row. The fees page title and label read "by fees". The fees description is "The 100 CCIP {dim}s that paid the most in fees, {scope}." The lane column is "Typical fee (30d)", with "—" for lanes `cost.json` doesn't list.
  - Day pages: the Fees sub-line "$X per message · Y% paid in LINK"; the Take rate tile "N bps", with the sub-line "of value moved".
- **Budgets:**
  - Home JavaScript ≤ 150 KB gzipped (`pnpm --filter @ccip-dev/site build` enforces it).
  - Lighthouse mobile accessibility ≥ 95 on Flow, Top and a day page.
  - No horizontal scroll at 390 px.
- **`.backfill/` is the owner's.** A live fee crawl runs there. Never write to it.
- **Remote operations are owner steps.** Never run a `wrangler … --remote` command. A push to `main` deploys the Worker and the site.
- **Commits:**
  - Conventional subjects (`feat(worker): …`, `feat(site): …`).
  - Stage explicit paths only. Never use `git add -A`, `git add .` or `git commit -a`.
  - End each message with the implementer's `Co-Authored-By` trailer.
- **Tests:**
  - Core: `pnpm --filter @ccip-dev/core test`.
  - Worker: `pnpm --filter @ccip-dev/worker test`.
  - Site: `pnpm --filter @ccip-dev/site test`. This runs both the node and the workerd configs.
  - Types: `pnpm typecheck`.

## Review Focus

1. **The site builds before the Worker's first `cost.json`.** A push deploys the Worker and the site together, but `cost.json` only appears at the next finalize (00:10 or 06:00 UTC). The build must pass, with "—" in the typical-fee column. The picker must then say the data is not available, not hang on its skeleton.
   - Tests: in Task 4, `buildDataIfPublished` "returns null while the Worker has not published the file yet", and `CostPanel` "says the data is not available when cost.json could not be read".
2. **Fees under a cent and take rates under 1 bps.** A typical CCIP fee is about $0.50, and a typical day's take rate is about 0.24 bps (live `history.json`, 2026-10). `formatUsd` would print these as "$1" and "$0", and rounding `cost.json` to cents would zero out sub-cent medians.
   - Tests: Task 2 "keeps four decimals for a route whose fees are fractions of a cent"; the Task 4 `formatFee` cases; the Task 5 `formatBps` cases.
3. **A hand-typed or stale picker link.** Examples: `?from=Ethereum&to=BASE`, a chain added since the last site build, and the same chain twice.
   - Each must open a sensible route or the "Not enough messages" line, never a blank picker.
   - Tests: in Task 4, `routeFromQuery` "reads a hand-typed name in any case", "resolves a chain the build did not know by its selector" and "treats the same chain twice as a route without data".
4. **LINK fee tokens stored in another letter case.** The LINK split runs in SQL against `chain:normalizedAddress` keys. An EVM address must match whatever its case, but Solana's base58 LINK must match case for case.
   - Tests: Task 2's percentile fixture pays in the checksummed `LINK_TOKEN`, and "counts LINK from the registry group, matching a Solana address case for case".
5. **A route paid entirely in LINK.** It has no non-LINK fee, so it has no gas median. The picker must show only the LINK median, never "in gas tokens: —".
   - Tests: Task 2's Solana test expects no `gas`; Task 4 "shows only the LINK median for a route paid entirely in LINK".

## Decisions the spec leaves open or gets wrong

- **Tokens get no fee ranking.** The spec lists `/top/token/{window}/fees/`. Token rows in `daily_breakdown` never carry a fee: `rollupDay` builds them with `withFees = false`, because a message's fee is not split across its tokens. Every live `top/token.json` entry has `fee_usd: null`, so a token fees page would always be empty.
  - The Worker publishes `by_fees` for `src_chain`, `dst_chain`, `lane` and `sender` only.
  - The site's fees switch, pages and cards cover lanes, senders and chains.
  - The token pages show no "Value | Fees" row, and `/og/top/token/{window}/fees.png` is a 404.
  - This builds 12 new pages, not the spec's estimate of about 24.
- **`cost.json` before its first publish.** Spec §7 says the site builds against the older files "because the new fields are optional", but `cost.json` is a new file, and the build fails on a missing file.
  - Top lanes read it through `buildDataIfPublished`, which returns null on HTTP 404 only.
  - The runbook's "Build failures" names this one exception.
- **One row per route.** The cost query keeps only the percentile ranks inside SQL and folds them into one row per route with `MAX(CASE …)`. That satisfies "no message rows pass through the Worker" with fewer rows than "a few rows per route".
- **No `gas` when nothing was paid outside LINK.** A route that qualifies for the split, but paid every fee in LINK, has no non-LINK median, so `gas` is left out. The picker then shows only "Paid in LINK: $X".
- **Four decimals in `cost.json`.** Other public files round USD to cents, which would turn a $0.004 median into $0.
- **Picker names are chain slugs.** `<chain name>` in `?from=&to=` uses the same slug as `/replay/<slug>/` (`slugMap(replay.chains)`, for example `ethereum` or `base`).
  - Matching is case-insensitive.
  - A chain new since the last site build is addressed by its selector.
- **Icons in the result line.** A native `<select>` cannot hold images, so the chain icons sit beside the route name in the result.
- **Share on a fees page is the share of fees.** A value share in a fee ranking would be misleading. The footnote says which one it is.
- **Formats.**
  - `formatFee` shows cents below $1,000, and "<$0.01" for a positive fee under a cent.
  - `formatBps` keeps two decimals under 1 bps, one under 10, and shows "<0.01 bps" below that.
  - `formatShare` shows an unsigned whole percent, and "<1%" for a small share.
- **Top lanes means `/top/lane/…`.** The spec places the "Typical fee (30d)" column under Top pages (§5.2). The Flow page's own "Top lanes" table is unchanged.
- **The take-rate chart follows the fees chart.** It starts where fee data starts, as the fees chart does (`feeChartRows`). It carries the note "Fees as basis points of value moved.", per the spec's risk table.
- **Flow has no budget of its own.** `site/scripts/check-budgets.ts` budgets only `index.html` (150 KB) and `replay/index.html` (200 KB). §2.7 asks only that the existing checks hold, so the plan adds no Flow budget. The picker is about one small island, plus the chain-icon manifest that `ChainIcons.tsx` already imports.
- **Fee rankings and the free D1 plan.** The fee rankings add 12 `daily_breakdown` scans per publish (the token dim is skipped). The all-time ones read every row of their dim, as the value rankings already do. The plan follows the spec. After the first two publishes, the owner should compare the D1 dashboard's daily rows read with the free plan's 5 million.

## Local preview with `by_fees` and `cost.json`

Tasks 3, 4 and 5 check the built site in a browser. Until the Worker change is live, `data.ccip.dev` has no `by_fees`, no `cost.json` and no fee-group fields, so the preview builds against a local mirror that adds synthetic ones. The mirror is for looking only: never commit it.

1. Save this as `mirror.mjs` in your scratch directory.

```js
import { mkdir, writeFile } from 'node:fs/promises';
import path from 'node:path';

const dir = process.argv[2];
if (!dir) throw new Error('usage: node mirror.mjs <directory>');
const FILES = ['status', 'live', 'today', 'history', 'top/lane', 'top/token', 'top/sender', 'top/src_chain', 'top/dst_chain', 'chains', 'tokens', 'reserve', 'replay'];
const get = async (name) => {
  const res = await fetch(`https://data.ccip.dev/v1/${name}.json`, { headers: { 'user-agent': 'curl/8.7.1' } });
  if (!res.ok) throw new Error(`${name}.json: HTTP ${res.status}`);
  return res.json();
};
const round = (v, places = 2) => Math.round(v * 10 ** places) / 10 ** places;
const files = Object.fromEntries(await Promise.all(FILES.map(async (f) => [f, await get(f)])));

for (const d of files.history.days) {
  if (d.fee_usd === null || d.fee_native_usd != null) continue;
  const link = d.fee_link_usd ?? round(d.fee_usd * 0.2);
  Object.assign(d, { fee_link_usd: link, fee_native_usd: round(d.fee_usd * 0.55), fee_stable_usd: round(d.fee_usd * 0.15), fee_link_amount: round(link / 12) });
}

const byFee = (entries) => entries.filter((e) => e.fee_usd != null).sort((a, b) => b.fee_usd - a.fee_usd || (b.usd ?? 0) - (a.usd ?? 0));
for (const dim of ['lane', 'sender', 'src_chain', 'dst_chain']) {
  const top = files[`top/${dim}`];
  top.by_fees ??= { '7d': byFee(top.windows['7d']), '30d': byFee(top.windows['30d']), all: byFee(top.windows.all) };
}

const lastDay = files.history.days.at(-1).day;
const shift = (day, n) => new Date(Date.parse(`${day}T00:00:00Z`) + n * 86_400_000).toISOString().slice(0, 10);
const synthCost = () => ({
  schema_version: 1,
  updated_at: new Date().toISOString(),
  attribution: files.history.attribution,
  from: shift(lastDay, -29),
  to: lastDay,
  lanes: files['top/lane'].windows['30d']
    .filter((e) => e.messages >= 5 && e.fee_usd != null)
    .sort((a, b) => b.messages - a.messages)
    .map((e) => {
      const [src, dst] = e.key.split('>');
      const mean = e.fee_usd / e.messages;
      const lane = { src, dst, messages: e.messages, median_usd: round(mean * 0.8, 4), p10_usd: round(mean * 0.3, 4), p90_usd: round(mean * 2.5, 4) };
      const linkMessages = Math.round(e.messages * 0.3);
      return linkMessages >= 20
        ? { ...lane, link: { messages: linkMessages, median_usd: round(mean * 0.7, 4) }, gas: { messages: e.messages - linkMessages, median_usd: round(mean * 0.85, 4) } }
        : lane;
    }),
});
files.cost = await get('cost').catch(() => synthCost());

for (const [name, body] of Object.entries(files)) {
  const file = path.join(dir, 'v1', `${name}.json`);
  await mkdir(path.dirname(file), { recursive: true });
  await writeFile(file, JSON.stringify(body));
}
console.log(`mirrored ${Object.keys(files).length} files to ${dir}/v1; cost.json lists ${files.cost.lanes.length} routes, ${files.cost.lanes.filter((l) => l.link).length} with a LINK split`);
```

2. Save this as `serve.mjs` in the same directory. It serves the mirror with CORS, because the Flow picker fetches `cost.json` from the browser.

```js
import { createServer } from 'node:http';
import { readFile } from 'node:fs/promises';
import path from 'node:path';

const [dir, port = '8799'] = process.argv.slice(2);
if (!dir) throw new Error('usage: node serve.mjs <directory> [port]');
const root = path.resolve(dir);
createServer(async (req, res) => {
  const cors = { 'access-control-allow-origin': '*' };
  const file = path.join(root, decodeURIComponent(new URL(req.url ?? '/', 'http://localhost').pathname));
  if (!file.startsWith(root)) return res.writeHead(403, cors).end();
  try {
    res.writeHead(200, { ...cors, 'content-type': 'application/json; charset=utf-8' }).end(await readFile(file));
  } catch {
    res.writeHead(404, cors).end('missing');
  }
}).listen(Number(port), () => console.log(`serving ${root} on http://localhost:${port}`));
```

- `sqlite_version()` is not authorized in D1.
- `ceil()` exists locally. The query still uses integer arithmetic, which every SQLite build has.
- **Nearest rank:** of n fees in ascending order, the p-th percentile is the fee at rank ⌈p·n/100⌉. In integer arithmetic that is `(p * n + 99) / 100`, exact for whole p and n ≥ 1. For example, n = 25 gives p10 = rank 3, p50 = rank 13 and p90 = rank 23.

- **Size:** `replay.json` counts about 52,000 messages in the last 30 days, with about 270 routes at 5 or more messages and about 150 at 20 or more. This is well under the spec's estimate of 300k rows.

```ts
export interface FeeCostRow {
  src: string;
  dst: string;
  messages: number;
  link_messages: number;
  p10_usd: number;
  median_usd: number;
  p90_usd: number;
  link_median_usd: number | null;
  gas_median_usd: number | null;
}

/** A fee token as normalizeAddress stores it: a 42-character 0x address lowercased, any other address as it is. */
const NORMALIZED_FEE_TOKEN = "CASE WHEN fee_token LIKE '0x%' AND length(fee_token) = 42 THEN lower(fee_token) ELSE fee_token END";

/**
 * One row per route over days [?1, ?2] with at least ?3 priced fees: the nearest-rank 10th, 50th and 90th percentiles
 * (rank ceil(p·n/100), written (p·n + 99) / 100 in integer arithmetic), and the medians of the LINK-paid and other fees.
 * The LINK keys are inlined as literals because D1 caps a statement at 100 bound parameters.
 */
export function feeCostsSql(linkTokens: LinkFeeTokens): string {
  const keys = [...linkTokens.keys()].map(sqlLiteral).join(', ');
  return `WITH priced AS (
      SELECT src_chain, dst_chain, fee_usd,
        CASE WHEN (src_chain || ':' || ${NORMALIZED_FEE_TOKEN}) IN (${keys}) THEN 1 ELSE 0 END AS is_link
      FROM messages WHERE day >= ?1 AND day <= ?2 AND fee_usd IS NOT NULL
    ), ranked AS (
      SELECT src_chain, dst_chain, fee_usd, is_link,
        ROW_NUMBER() OVER (PARTITION BY src_chain, dst_chain ORDER BY fee_usd) AS rn,
        COUNT(*) OVER (PARTITION BY src_chain, dst_chain) AS n,
        ROW_NUMBER() OVER (PARTITION BY src_chain, dst_chain, is_link ORDER BY fee_usd) AS split_rn,
        COUNT(*) OVER (PARTITION BY src_chain, dst_chain, is_link) AS split_n,
        SUM(is_link) OVER (PARTITION BY src_chain, dst_chain) AS link_n
      FROM priced
    )
    SELECT src_chain AS src, dst_chain AS dst, MAX(n) AS messages, MAX(link_n) AS link_messages,
      MAX(CASE WHEN rn = (10 * n + 99) / 100 THEN fee_usd END) AS p10_usd,
      MAX(CASE WHEN rn = (50 * n + 99) / 100 THEN fee_usd END) AS median_usd,
      MAX(CASE WHEN rn = (90 * n + 99) / 100 THEN fee_usd END) AS p90_usd,
      MAX(CASE WHEN is_link = 1 AND split_rn = (50 * split_n + 99) / 100 THEN fee_usd END) AS link_median_usd,
      MAX(CASE WHEN is_link = 0 AND split_rn = (50 * split_n + 99) / 100 THEN fee_usd END) AS gas_median_usd
    FROM ranked
    WHERE n >= ?3
    GROUP BY src_chain, dst_chain
    ORDER BY messages DESC, src, dst`;
}

export async function feeCosts(db: D1Database, fromDay: string, toDay: string, linkTokens: LinkFeeTokens, minMessages: number): Promise<FeeCostRow[]> {
  const { results } = await db.prepare(feeCostsSql(linkTokens)).bind(fromDay, toDay, minMessages).all<FeeCostRow>();
  return results;
}
```

```ts
import type { TopEntry, TopFile } from '@ccip-dev/core/public';
import type { TopDim, TopOrder, Window } from './card-paths';
import { chainName, keyChains, laneLabel, senderLabel, tokenLabel, type ChainNames } from './names';

export type TopFileName = 'top/lane.json' | 'top/token.json' | 'top/sender.json' | 'top/src_chain.json';

/** The Chains tab ranks source chains, so it reads the src_chain file. */
export const TOP_FILE: Record<TopDim, TopFileName> = {
  lane: 'top/lane.json',
  token: 'top/token.json',
  sender: 'top/sender.json',
  chain: 'top/src_chain.json',
};

export interface TopRow {
  rank: number;
  primary: string;
  secondary: string | null;
  verified: boolean;
  chains: string[];
  messages: number;
  usd: number | null;
  fee: number | null;
  sharePct: number | null;
}

export interface TopRowOptions {
  order?: TopOrder;
}

export function topHref(dim: TopDim, window: Window, order: TopOrder): string {
  return `/top/${dim}/${window}/${order === 'fees' ? 'fees/' : ''}`;
}

/** A file published before the fee rankings has no by_fees, so its fees pages show their empty state. */
export function topEntries(top: TopFile, window: Window, order: TopOrder): TopEntry[] {
  return order === 'fees' ? (top.by_fees?.[window] ?? []) : top.windows[window];
}

function rowLabel(e: TopEntry, dim: TopDim, names: ChainNames): { primary: string; secondary: string | null; verified: boolean } {
  if (dim === 'lane') return { primary: laneLabel(names, e.key), secondary: null, verified: false };
  if (dim === 'chain') return { primary: chainName(names, e.key), secondary: null, verified: false };
  if (dim === 'token') return { ...tokenLabel(names, e.key, e.symbol), verified: false };
  return senderLabel(names, e.key, e.label);
}

export function topRows(entries: readonly TopEntry[], dim: TopDim, names: ChainNames, opts: TopRowOptions = {}): TopRow[] {
  const measure = (e: TopEntry) => (opts.order === 'fees' ? (e.fee_usd ?? null) : e.usd);
  const total = entries.reduce((sum, e) => sum + (measure(e) ?? 0), 0);
  return entries.map((e, i) => {
    const m = measure(e);
    return {
      rank: i + 1,
      ...rowLabel(e, dim, names),
      chains: dim === 'chain' ? [e.key] : keyChains(e.key),
      messages: e.messages,
      usd: e.usd,
      fee: e.fee_usd ?? null,
      sharePct: total > 0 && m !== null ? (m / total) * 100 : null,
    };
  });
}
```

```ts
import type { CostFile, CostLane } from '@ccip-dev/core/public';

export interface CostChain {
  selector: string;
  name: string;
  slug: string;
}

export interface CostRoute {
  src: string;
  dst: string;
  lane: CostLane | null;
}

export interface ChainIndex {
  bySelector: ReadonlyMap<string, CostChain>;
  bySlug: ReadonlyMap<string, string>;
}

export function chainIndex(chains: readonly CostChain[]): ChainIndex {
  return { bySelector: new Map(chains.map((c) => [c.selector, c])), bySlug: new Map(chains.map((c) => [c.slug, c.selector])) };
}

/** A chain new since the last site build is named by its selector, which is also its slug. */
export function chainOf(index: ChainIndex, selector: string): CostChain {
  return index.bySelector.get(selector) ?? { selector, name: selector, slug: selector };
}

function busiest(lanes: readonly CostLane[]): CostLane | null {
  return lanes.reduce<CostLane | null>((best, l) => (best === null || l.messages > best.messages ? l : best), null);
}

export function routeOf(cost: CostFile, src: string, dst: string): CostRoute {
  return { src, dst, lane: cost.lanes.find((l) => l.src === src && l.dst === dst) ?? null };
}

export function defaultRoute(cost: CostFile): CostRoute | null {
  const lane = busiest(cost.lanes);
  return lane === null ? null : { src: lane.src, dst: lane.dst, lane };
}

/** Reads `?from=<slug>&to=<slug>`. A name that is not a known chain falls back to the busiest route. */
export function routeFromQuery(cost: CostFile, index: ChainIndex, search: string): CostRoute | null {
  const params = new URLSearchParams(search);
  const listed = new Set(cost.lanes.flatMap((l) => [l.src, l.dst]));
  const resolve = (name: string | null): string | null => {
    const key = (name ?? '').trim().toLowerCase();
    return index.bySlug.get(key) ?? (listed.has(key) ? key : null);
  };
  const src = resolve(params.get('from'));
  const dst = resolve(params.get('to'));
  return src !== null && dst !== null ? routeOf(cost, src, dst) : defaultRoute(cost);
}

export function routeQuery(index: ChainIndex, route: Pick<CostRoute, 'src' | 'dst'>): string {
  return `?${new URLSearchParams({ from: chainOf(index, route.src).slug, to: chainOf(index, route.dst).slug }).toString()}`;
}

/** The selected chain stays listed even without data, so a route opened from a link still shows in the selects. */
function options(index: ChainIndex, selectors: readonly string[], selected: string | null): CostChain[] {
  const all = new Set(selectors);
  if (selected !== null) all.add(selected);
  return [...all].map((s) => chainOf(index, s)).sort((a, b) => a.name.localeCompare(b.name, 'en'));
}

export function sourceOptions(cost: CostFile, index: ChainIndex, selected: string | null): CostChain[] {
  return options(index, cost.lanes.map((l) => l.src), selected);
}

export function destinationOptions(cost: CostFile, index: ChainIndex, src: string, selected: string | null): CostChain[] {
  return options(index, cost.lanes.filter((l) => l.src === src).map((l) => l.dst), selected);
}

/** After From changes, To stays when the new source has data for it; otherwise it moves to the source's busiest destination. */
export function routeForSource(cost: CostFile, src: string, dst: string): CostRoute {
  const current = routeOf(cost, src, dst);
  if (current.lane !== null) return current;
  const lane = busiest(cost.lanes.filter((l) => l.src === src));
  return lane === null ? current : { src, dst: lane.dst, lane };
}
```

```ts
/** A day's take rate is usually under 1 bps, so small values keep two decimals. */
export function formatBps(value: number | null | undefined): string {
  if (!usable(value)) return DASH;
  if (value > 0 && value < 0.01) return '<0.01 bps';
  return `${value.toFixed(value < 1 ? 2 : value < 10 ? 1 : 0)} bps`;
}

/** A part of a whole, unsigned; formatPct signs changes. */
export function formatShare(pct: number | null | undefined): string {
  if (!usable(pct)) return DASH;
  if (pct > 0 && pct < 1) return '<1%';
  return `${Math.round(pct)}%`;
}
```

```ts
  return FEE_MIX_SERIES.map((s) => ({ ...s, usd: usd[s.key], pct: (usd[s.key] * 100) / total }));
}
```
